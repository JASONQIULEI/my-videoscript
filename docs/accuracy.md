# 如何评估转写准确率

项目把「生成了文稿」「网页可以取回文稿」和「文稿内容正确」分开验证。单元测试覆盖前两者的部分行为；内容准确率需要独立参考稿。

## 当前开发样本

一条约 13 分 54 秒的中文视频，在字幕优先流程下生成 645 个输出片段。参考稿独立核对原视频画面字幕，共 4,605 个归一化字符，全文字符对齐计得 8 次编辑：

```text
CER = 8 / 4605 = 0.1737%
字符准确率 = 1 - CER = 99.8263%
```

这个数字的适用范围是该视频的画面字幕文字：

- 样本参与过算法调试，不是独立留出测试集，不能推断新视频效果。
- 它不验证口播逐字准确率；画面字幕可能省略或改写口头表达。
- 它不验证每个字幕时间戳的精度。
- 无字幕内容使用语音识别，尚无足够参考样本支持「99%」的结论。
- 参考稿、原片和完整输出未随仓库发布，以上是开发记录，不是随源码可复现的公开基准。

保留的错误包括个别同音或形近字、重复字和少量漏字。质量提示仅辅助定位问题，不保证找出所有错误。

## 使用评分工具

先从原始来源独立整理参考稿，再运行待评测流程。不要直接拿模型输出改几个字就称为独立参考；也不要把参考稿内容写进生产代码来提高分数。

参考文件 `reference.json` 的格式如下。示例文字是合成内容，与开发样本无关：

```json
{
  "windows": [
    {
      "start": 0,
      "end": 10,
      "segments": [
        {"text": "今天介绍字幕识别。"},
        {"text": "准确率需要独立核对。"}
      ]
    }
  ]
}
```

候选文件 `candidate.json` 可以是任务导出的 `segments.json`，也可以是片段数组：

```json
[
  {"start": 0, "end": 4, "text": "今天介绍字幕识别。"},
  {"start": 4, "end": 9, "text": "准确率需要独立核对。"}
]
```

```bash
python3 evaluation/score.py \
  --reference reference.json \
  --candidate candidate.json \
  --output score.json
```

评分工具只使用 Python 标准库，可在不安装识别依赖的情况下运行。以上完全相同的合成文本应得到 0 次编辑、100% 一致率；这只用于检查评分工具能运行。

## 评分规则

- 按参考时间窗计分，时间窗必须有正时长且互不重叠；候选片段以中点时间归入时间窗。
- 使用 NFKC 归一化并转小写，忽略空白及大多数排版标点。
- 保留百分号、千分号、数字间的小数点与范围分隔符等；不把 `27.75` 当成 `2775`，不把 `70%` 当成 `70`。
- 不进行繁简转换或数字读法转换；逗号千位分隔符被忽略。
- 使用 Levenshtein 字符编辑距离，计入替换、删除和插入；总分按参考字符数量加权。
- `1 - CER` 在错误很多时可以小于零，不能把它当作模型概率。

参考稿不能是空白内容。评测输出会包含参考稿和候选文本，因此也可能包含私人内容；请把评测文件放在仓库之外，或放在已忽略的 `evaluation/` 本地目录中。

## 扩展验收

增加未参与调试的新样本，分别覆盖不同字幕样式、纯音频、口音、背景音乐和说话速度；字幕与语音两条流程分别统计。报告样本数量、时长、字符数、错误数及规则，并单独复核姓名、公司名、金额、百分比、否定关系等会改变意思的内容。
